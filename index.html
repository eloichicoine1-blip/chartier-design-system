Architecture CSS

Le fichier style.css est rangé en couches @layer. L'ordre est déclaré une fois en tête du fichier : une règle d'une couche placée plus loin dans la liste l'emporte toujours, quelle que soit la spécificité de son sélecteur. On sait donc où écrire chaque style, et quoi copier dans le thème WordPress.

@layer reset, tokens, base, typography, components, ds-page;
  1. reset Remise à zéro des styles du navigateur (Piccalilli). Page de démonstration seulement
  2. tokens Variables primaires (valeurs Figma) et secondaires (rôles : --color-primary, --space-l…). Copiée dans le thème
  3. base Styles des balises : corps de page, liens, images. Page de démonstration seulement
  4. typography Blocs .heading et .text : titres, textes, libellés. Reprise par le thème (titres, prix)
  5. components Composants BEM : boutons, badges, champs, cartes, navigation, messages. Copiée dans le thème
  6. ds-page Mise en page de cette page : sommaire, grilles, nuanciers. Page de démonstration seulement

Dans le thème enfant WordPress, les styles des composants restent hors couche : le CSS de Storefront et de WooCommerce n'est pas en couches, et une règle hors couche l'emporte sur toutes les règles en couche. Les copier en couche les ferait passer derrière Storefront.
